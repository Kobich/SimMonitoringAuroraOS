# Архитектура SIM Monitor

## Требования

- При старте мониторинга читаем состояние SIM/сети и обязательно отправляем первое уведомление.
- При изменении SIM, типа сети (нет сети, 2G, 3G, 4G, 5G), оператора или MCC/MNC отправляем уведомление.
- Изменения dBm не уведомляют: они слишком частые.
- Настройка «мониторинг включён» переживает перезапуск.
- После закрытия UI/перезагрузки мониторинг восстанавливается разрешённым Aurora-механизмом.

## Слои

- presentation — экран и действия пользователя.
- application — start / stop / restore, правило уведомлений.
- domain — CellularSnapshot и сравнение состояний.
- data — контракт источника, mock, будущий Aurora-источник.
- platform — модем, уведомления и автозапуск Aurora.

CellularMonitoringController реализует главный сценарий: сохраняет включение, показывает первое уведомление, слушает поток изменений и уведомляет только при значимом отличии.

## Проверка на эмуляторе

1. RPM устанавливается и открывается.
2. Доступные API для SIM и radio access type.
3. Механизм фоновой работы и автозапуска.
4. Системные уведомления.

Нативная Aurora-реализация будет в platform/ и реализует CellularDataSource.watch(). Android Service не копируем: сначала подтверждаем доступный механизм Aurora.
